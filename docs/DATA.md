# Data and reproduction guide

Splat2BIM is a site-specific research pipeline. The repository contains the code,
tests, selected figures, and compact measurement records. The original captures,
full exported scenes, and pretrained weights must be supplied separately.

## What is kept out of Git

| Local content | Approximate existing size | Git policy |
|---|---:|---|
| `assets/`: captures, photographs, COLMAP, IFC | 13 GB | Entire directory excluded |
| `results/`: full scenes and experiment intermediates | 6.7 GB | Only selected compact evidence included |
| `.venv/` | 1.5 GB | Recreate from `requirements.txt` |
| `models/`: pretrained weights | 119 MB | Configurations/provenance included; weights excluded |
| `viewer/node_modules/` | 48 MB | Recreate with `npm ci --prefix viewer` |

Some JSON fit traces exceed 300 MB. The result rules in `.gitignore` use an
allowlist, so these remain local even though they are text files. Adding a new
publication figure requires an explicit exception. Ignoring files does not delete
them from the working project.

## Required input layout

Paths are relative to the repository root. Date identifiers are `MMDD` strings;
keep their leading zeroes.

```text
assets/
├── 0331/0331.ply + 0331.las
├── 0504/0504.ply + 0504.las
├── 0609/0609.ply + 0609.las
├── 0708/0708.ply + 0708.las
├── 0723/0723.ply + 0723.las
├── 0831/0831.ply + 0831.las
├── 0929/
│   ├── 0929.ply
│   ├── 0929.las
│   ├── photos/                 Original DJI images with embedded RTK metadata
│   └── colmap/
│       ├── cameras.txt
│       ├── images.txt
│       └── points3D.txt
└── BIM/
    ├── The Loop Federated Model v1.ifc
    ├── The Loop Federated Model v2.ifc
    └── The Loop Federated Model v3.ifc
```

The PLY inputs are Gaussian scenes, with position, opacity, quaternion rotation,
log-scale, DC color, and degree-3 spherical-harmonic fields. Ordinary colored
point-cloud PLYs are not interchangeable with these inputs. LAS files provide the
reference geometry and color. The existing `.psht`, `.abc`, and binary COLMAP
files are not required by the baseline commands below.

The 0929 dataset used 1,586 available images out of 1,759 COLMAP records. The
RTK-assisted alignment uses the available matches. The camera-localization
experiment also needs those original photographs.

No public dataset download is bundled. Existing input manifests record hashes
for the geometric inputs used in the experiments. Substituting different data
requires adapting site-specific assumptions and re-evaluating the results.

## Coordinate conventions

- Local outputs are in metres, with origin **`[825800, 842100, 0]`** subtracted
  from the LAS/IFC coordinate values.
- A local-to-global conversion adds that origin once. A saved `*_global.txt`
  transformation already includes it; do not add it again.
- Matrices use homogeneous column vectors: `p_destination = T @ [x, y, z, 1]`.
- IFC geometry is placed using its world coordinates and the same origin.
  No separate BIM alignment is fitted.
- EPSG:2326 is the documented horizontal working assumption. Independent vertical
  control and the authoritative BIM revision for each date remain unconfirmed.

## Rebuild the baseline viewer

Run from the repository root after restoring inputs and installing the Python/npm
dependencies in the [README](../README.md#getting-started). These commands generate
large files and overwrite their own result artifacts. Use a separate checkout if
you want to preserve an existing experiment run byte for byte. The recorded local
project uses about 21 GB in total; allow extra space for new experiments.

```bash
source .venv/bin/activate
export OPENBLAS_NUM_THREADS=4
export OMP_NUM_THREADS=4

# RTK/COLMAP-assisted 0929 registration and complete Gaussian export.
python scripts/align_0929.py
python scripts/export_3dgs.py
python scripts/preview_0929.py

# IFC tessellation and the 0929 LAS preview in the same local frame.
python scripts/prepare_bim.py
python scripts/report_bim.py

# The other six capture dates and the viewer's date manifest.
python scripts/align_dates.py
python scripts/export_dates.py
python scripts/compare_dates.py
python scripts/preview_dates.py

# Quality layers; the fixed region definitions are included in Git.
python scripts/check_common_areas.py
python scripts/check_static_structures.py
python scripts/report_static_structures.py

python scripts/serve_viewer.py
```

Then open [http://127.0.0.1:8765/viewer/](http://127.0.0.1:8765/viewer/).
The full PLY scenes load one date at a time. LAS previews show every tenth point;
the numerical comparisons use the full LAS reference. The viewer links to
additional experiment pages, which must be generated by their respective report
scripts before those links work locally.

## Optional semantic models

The base registration and synthetic tests do not need pretrained weights. The
semantic experiments load two models from local folders and use their recorded
configurations. Their exact upstream revisions and SHA-256 values are committed:

| Model | Local folder | Provenance |
|---|---|---|
| Aerial SegFormer-B0 | `models/drone_segformer_b0/` | [Revision and hashes](../models/drone_segformer_b0/provenance.json) |
| LoveDA SegFormer-B2 | `models/loveda_segformer_b2/` | [Revision and hashes](../models/loveda_segformer_b2/provenance.json) |

Obtain the weights under the upstream model terms. The aerial model's recorded
license label is `other`; this repository does not relicense or redistribute its
weights. With the pinned Python environment active, the following downloads only
the files listed in each provenance record and verifies every file before use:

```bash
python - <<'PY'
import hashlib
import json
import shutil
from pathlib import Path
from huggingface_hub import hf_hub_download

for folder in (Path('models/drone_segformer_b0'), Path('models/loveda_segformer_b2')):
    provenance = json.loads((folder / 'provenance.json').read_text())
    for name, expected in provenance['files'].items():
        destination = folder / name
        if destination.exists() and hashlib.sha256(destination.read_bytes()).hexdigest() == expected:
            continue
        upstream_name = 'README.md' if name == 'MODEL_CARD.md' else name
        cached = hf_hub_download(
            repo_id=provenance['repository'],
            revision=provenance['revision'],
            filename=upstream_name,
        )
        assert hashlib.sha256(Path(cached).read_bytes()).hexdigest() == expected, name
        shutil.copyfile(cached, destination)
        print('Verified:', destination)
PY
```

The Gaussian-view projection renderer also requires `clang++`. Its native library
is compiled into `.cache/` on first use; that cache is excluded from Git.

## Experiment dependencies

The research scripts are sequential experiments, not a single general-purpose
training CLI. Most later stages read the complete outputs of earlier stages;
the compact CSV/JSON files in Git do not replace arrays or detailed fit traces.

| Stage | Main entry points | Required earlier artifacts |
|---|---|---|
| Fixed-structure evaluation | `check_static_structures.py` | Baseline registrations, raw PLY/LAS, tracked region definitions |
| Object initialization | `align_objects.py`, `align_object_consensus.py`, `align_object_recovery.py` | Baseline registrations and object/control pools from preceding stages |
| Semantic matching | `prepare_semantic_clouds.py`, `align_semantic.py`, `align_semantic_initial.py` | Object pools, raw inputs, aerial weights |
| Building-label fusion | `prepare_semantic_structures.py`, `prepare_semantic_fusion.py`, `align_semantic_fusion.py` | Earlier labels/pools and LoveDA weights |
| Gaussian-view labels | `prepare_semantic_3dgs.py`, `align_semantic_3dgs.py` | Fusion outputs, source Gaussians, renderer/compiler |
| Persistent surfaces | `prepare_stable_structures.py`, `align_stable_structures.py` | Semantic registration, geometric pools, all seven LAS dates |
| Accuracy refinement | `fit_structural_refinement.py`, `fit_guarded_structural_refinement.py`, `fit_reviewed_structural_refinement.py` | Complete persistent-surface results and fixed region definitions |
| Camera localization | `run_camera_localization.py`, `report_camera_localization.py` | 0929 baseline, photos/COLMAP, LAS, prepared BIM for overlays |

The [research notes](../RESEARCH_NOTES.md) document the initial stages. The
[persistent-structure report](../results/stable_structures/REPORT.md) and
[refinement report](../results/reviewed_structural_refinement/REPORT.md) describe
the later protocols. These archived instructions assume their prerequisites
already exist locally.

For refinement, evaluate **all three** generated experiment folders before
running the combined verifier:

```bash
python scripts/fit_structural_refinement.py
python scripts/fit_guarded_structural_refinement.py
python scripts/fit_reviewed_structural_refinement.py
python - <<'PY'
import sys
from pathlib import Path
sys.path.insert(0, 'scripts')
from evaluate_structural_refinement import main
for name in ('structural_refinement', 'guarded_structural_refinement', 'reviewed_structural_refinement'):
    main(Path('results', name).resolve())
PY
python -m unittest discover -s scripts -p 'test_*.py' -v \
  > results/guarded_structural_refinement/tests.log 2>&1
python scripts/verify_structural_refinement.py
python scripts/report_structural_refinement.py
```

Full verifiers require the original dataset and the complete parent experiments,
including their frozen inputs and recorded hashes. A new run can vary with
platform/library differences; the stored validation receipts describe the
original local runs. Keep any newly generated evidence distinct from those
receipts when making new accuracy claims.
